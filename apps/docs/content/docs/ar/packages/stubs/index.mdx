## الغرض

يحجز `packages/i18n/src/stubs/` ثلاث نقاط دخول لمنصات لا ينفّذها إصدار v1: React Native (`native`)
وخواديم Node (`node`) وElectron (`electron`). وكل واحدة تُصدّر مُنشئاً واحداً يرمي خطأً واضحاً موسوماً
بمرحلته.

## متى تستخدمه

لا ينبغي أن تستخدمها. فهي موجودة كي:

- تُحلّ المسارات الفرعية `@faang/i18n/native` و`@faang/i18n/node` و`@faang/i18n/electron` في خريطة
  صادرات الحزمة، و
- تفشل الشيفرة التي تمدّ يدها إلى منصة غير منفَّذة بصوت عالٍ عند موضع الاستدعاء بدل استيراد
  `undefined` والانهيار في موضع غير ذي صلة.

## الاستخدام

```ts
import { createNativeI18n } from '@faang/i18n/native'

createNativeI18n()
// Error: @faang/i18n/native is not implemented in v1. Track the v1.1 milestone.
```

## واجهة البرمجة

| التصدير | المسار الفرعي | الرسالة | المرحلة |
|---|---|---|---|
| `createNativeI18n` | `@faang/i18n/native` | `@faang/i18n/native is not implemented in v1...` | v1.1 |
| `createNodeI18n` | `@faang/i18n/node` | `@faang/i18n/node is not implemented in v1...` | v1.2 |
| `createElectronI18n` | `@faang/i18n/electron` | `@faang/i18n/electron is not implemented in v1...` | v1.3 |

نوع إرجاع كل دالة هو `never`: أي أنها ترمي دائماً.

## المعاملات والمُرجَع

الثلاث لا تستقبل وسائط. ولأن نوع الإرجاع `never` يعتبر TypeScript أي شيفرة بعد الاستدعاء غير قابلة
للوصول، فيكشف الاستخدام العَرَضي وقت الترجمة كما وقت التشغيل.

## السلوك والحالات الحدّية

- تسمّي رسالة الخطأ المسار الفرعي بدقة ومرحلة مستهدفة، فيصبح تقرير المشكلة قابلاً للتنفيذ.
- لا اعتماديات وقت تشغيل لهذه الوحدات، فاستيراد المسار الفرعي لا يجلب React ولا المُحمّل ولا i18next.
- الهياكل غير مُصدَّرة عمداً من نقطة الدخول الجذرية؛ يجب استيراد المسار الفرعي صراحةً، وهذا يُبقيها
  خارج التطبيقات التي لا تشير إليها أبداً.

## أنماط الفشل

ترمي دائماً `Error` بالرسالة أعلاه. ولا يوجد وضع لا أثر له صامت.
