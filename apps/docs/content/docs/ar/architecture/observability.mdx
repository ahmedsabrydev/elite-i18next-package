## اتحاد الأحداث

كل القياسات اتحاد مميّز واحد هو `I18nEvent`، معرّف في `packages/i18n/src/core/types.ts`:

| الحدث | الحقول | وقت الإطلاق |
|---|---|---|
| `ns.load` | `lng` و`ns` و`ms` و`bytes?` | اكتمل تحميل مساحة أسماء من طبقة غير الذاكرة |
| `ns.cache_hit` | `lng` و`ns` | خُدمت مساحة الأسماء من طبقة الذاكرة |
| `ns.timeout` | `lng` و`ns` و`ms` | بلغ المُحمّل مهلة الانتظار لتلك المساحة |
| `missing_key` | `lng` و`ns?` و`key` | طُلب مفتاح غير موجود |
| `locale.switch` | `from` و`to` | تغيّرت اللغة |

تصدر النواة نفسها `ns.load` و`ns.cache_hit` و`ns.timeout`. أما النوعان `missing_key`
و`locale.switch` فجزء من الاتحاد العام كي تصدرهما المحوّلات والتطبيقات عبر المساعد المُصدَّر
`emit`؛ وربطهما بالنواة عمل لاحق متتبَّع.

يحمل `ns.load` القيمة `ms` (زمن الجدار بالمللي ثانية) و`bytes` (طول `JSON.stringify` للموارد
المحمّلة). و`bytes` هو طول وحدات الشيفرة UTF-16 لا طول البايت على الشبكة، فهو حدّ أدنى
للكتالوجات غير اللاتينية مثل العربية.

## كيفية إصدار الأحداث

تشترك بالتمرير `onEvent` إلى `createI18n`. ولا تسجّل النواة أي شيء بنفسها.

```ts
const runtime = createI18n({
  locales: ['en', 'ar'] as const,
  defaultLocale: 'en',
  catalogs: { public: '/catalogs' },
  onEvent: (event) => {
    if (event.type === 'ns.load') metrics.timing('i18n.load', event.ms, { ns: event.ns })
  },
})
```

## الإصدار لا يفشل أبداً

تغلّف `emit` في `packages/i18n/src/obs/events.ts` الدالة في `try/catch` وتبتلع أي خطأ:

```ts
export function emit(onEvent, event) {
  if (!onEvent) return
  try {
    onEvent(event)
  } catch {
    // لا يجوز أن تكسر المراقبة العرض أو التحميل.
  }
}
```

هذا مقصود: لا يجوز لعميل قياس معطّل أن يُسقط الترجمة. والمقايضة أن `onEvent` الذي يرمي خطأً
يفشل صامتاً — فإن احتجت معرفة أن دالتك معطّلة فالتقط الخطأ وبلّغ عنه داخل دالتك.

## ما لا يُصدَر

لا يوجد حدث عام «فشل التحميل». فالمواصفة لا تعرّف هذا الحدث، وأي فشل غير متعلق بالمهلة (خطأ
404 أو شبكة أو JSON مشوّه) يُحسم إلى `undefined` ويعرض اللغة الاحتياطية. المهلات وحدها قابلة
للمراقبة عبر `ns.timeout`. وهذا تأجيل مقصود موثّق في مواصفة التصميم لا سهو.

## إصابة المخبأ مقابل التحميل

لا يُصدر `ns.cache_hit` إلا من طبقة الذاكرة، لأنها الطبقة الوحيدة التي تُفحص قبل مسار
الطلبات المتزامنة والمُحمّل. وإصابة المخزن الدائم (IndexedDB) ليست حدثاً منفصلاً؛ بل تظهر
كـ `ns.load` لأن القيمة يجب أن توضع في الذاكرة رغم ذلك.
