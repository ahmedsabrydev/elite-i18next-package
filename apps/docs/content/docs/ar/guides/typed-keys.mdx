## الغرض

تجعل المفاتيح المُنمَّطة `t('common.actions.save')` خطأ ترجمة حين لا يوجد المفتاح. وتولّد الحزمة
الأنواع الداعمة عبر `i18next-cli types` من JSON الكتالوجات.

## الملفات المولَّدة

| الملف | يولّده | الدور |
|---|---|---|
| `packages/i18n/src/@types/resources.d.ts` | `i18next-cli types` | يُصدّر افتراضياً واجهة `Resources` تحاكي كل مفتاح كتالوج |
| `packages/i18n/src/@types/i18next.d.ts` | `i18next-cli types` | يوسّع `CustomTypeOptions` في i18next |

يبدو `i18next.d.ts` هكذا:

```ts
// This file is automatically generated by i18next-cli, because it was not existing.
// You can edit it based on your needs: https://www.i18next.com/overview/typescript#custom-type-options
import type Resources from './resources';

declare module 'i18next' {
  interface CustomTypeOptions {
    enableSelector: false;
    defaultNS: 'common';
  }
}
```

## إعادة التوليد

```bash
pnpm i18n:extract
pnpm i18n:types
```

شغّل الاستخراج أولاً كي تكون الكتالوجات محدَّثة، ثم الأنواع. وارتكب الكتالوجات والملفين المولَّدين معاً.

## كيف يُفترض أن يعمل

يصف `resources.d.ts` شجرة المفاتيح بدقة، ويقرأها تكامل TypeScript في i18next عبر
`CustomTypeOptions.resources`. وبمجرد الوصل يصبح المفتاح الخاطئ خطأ نوع ويقترح المحرر مفاتيح حقيقية.

## الحالة الحالية في v1

يستورد `i18next.d.ts` المولَّد النوع `Resources` ويضبط `defaultNS: 'common'` و`enableSelector: false`،
لكنه **لا** يدمج `Resources` بعد في `CustomTypeOptions.resources`. وهذا الوصل تأجيل مسجَّل، لذا في v1
يُنمَّط `t()` بافتراضيات i18next لا بكتالوجك. ويمكنك الاشتراك محلياً بإضافة الحقل `resources` إلى
`CustomTypeOptions` في ملف إعلان مشروعك.

## السلوك والحالات الحدّية

- `defaultNS: 'common'` يعني أن `t('actions.save')` المجرد يُبحث عنه في `common`؛ وتتطلب مساحات الأسماء
  الأخرى `t('ns:key')` أو صيغة الخطاف `useT('ns')`.
- `keySeparator` هو `.` و`nsSeparator` هو `:`، فالصيغة الكاملة `<namespace>:<segment>.<segment>`.
- `removeUnusedKeys: false` يعني أن الاستخراج لا يحذف المفاتيح، فقد يحتوي نوع الموارد مفاتيح لم تعد
  مستخدمة.
